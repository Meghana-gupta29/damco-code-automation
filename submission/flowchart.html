Sabotage the app on a new branch

Plant 2 deliberate bugs on branch demo/sabotage. Master is untouched.
  • Automated Create branch, apply bugs, commit
    qa sabotage apply
    Bug 1: items list no longer filters by owner (users see each other's items). Bug 2: sign-up minimum password 8 → 10.
  • Show the planted bugs
    git -C ..\full-stack-fastapi-template diff master demo/sabotage
  • Automated Rebuild the running app from the sabotage branch
    qa app deploy
3

Detect: failures and impacted area

Same suite, broken app. The AI triages failures into defects and names the suspect code.
  • Automated Run all tests
    qa run --label sabotaged
  • AI Triage: group failures, classify, rank severity, point at the file (uses the diff since the last green build)
    qa triage
  • Automated Email the No-Go report
    qa email
    Open runs\<latest>\report.html and runs\<latest>\defects\DEF-00x.md to show the impacted modules.
3 failed: TC-017, TC-043, TC-005Verdict: No-Go DEF-001 Sev1: data leak in items.pyDEF-002 Sev3: password rule in models.py

Your decision per defect (Gate 2)

The AI only recommends. You choose, per defect, whether the code or the test is wrong. One of each.
  • Human Interactive prompt for each defect
    qa decide
    DEF-001 (data leak): press c = fix the CODE.   DEF-002 (password 8 → 10): press t = update the TEST. Choose by title: numbering may vary.
  • AI proposes, Human confirms each diff with y
    qa fix
    Code path: minimal diff restoring the owner filter, committed on the sabotage branch. Test path: boundary moves to 9 rejected / 10 accepted, and the approved plan is amended with an audit trail.

A developer's PR keeps the automation up to date

New feature (item search) arrives as a real pull request. The QA agent reads it, adds tests for it, and re-runs: 48 → 50 tests.
  • Automated Plays the developer: feature branch + a real PR on your fork. Note the PR number it prints.
    qa feature apply --pr
  • AI QA agent reads the PR: impact analysis, existing cases at risk, proposes 1 API + 1 UI case
    qa pr-sync --pr 1
    Use the PR number printed above. Review runs\<latest>\test_cases.json: new cases TC-050 (API) and TC-051 (UI).
  • Human Gate 1 again: approve the new cases (optional: run qa run first to show it refusing)
    qa approve plan
  • AI Writes tests ONLY for the new cases, in new files. Existing tests untouched.
    qa generate all --new-only
  • Automated Deploy the PR branch, run everything, email
    qa app deploy qa run --label pr-feature qa email start dashboard\index.html
50 / 50 passed (32 API + 18 UI)Verdict: Go Report adds "Change under test" and the new cases.
