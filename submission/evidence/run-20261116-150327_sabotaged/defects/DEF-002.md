# DEF-002: Sign-up minimum password length raised from 8 to 10; boundary test still expects 8

- **Severity:** Sev3
- **Status:** Fixed (pending verification)
- **Classification (AI):** test_issue (confidence: medium)
- **AI recommendation:** update_test
- **Failing tests:** TC-005
- **Suspect module:** `backend/app/models.py` UserRegister.password: Field(min_length=8 -> min_length=10, max_length=128)
- **Regression since app commit:** aabb901
- **Run:** run-20261116-150327

## Root cause (AI)
UserRegister.password min_length was changed from 8 to 10, so POST /users/signup now returns 422 for an 8-character password. The test and plan still assume an 8-character minimum.

## Why this classification
Stricter password length looks like a deliberate security-policy change and not a defect, so the test is outdated. This is uncertain, because the change is only on UserRegister. UserCreate, UserUpdate, UpdatePassword and NewPassword still use min 8, and that inconsistency could be accidental. A human should confirm the intended policy. If 10 is intended, update TC-005 to use 10 and 128 as valid, 9 as invalid, and 129 as invalid, and decide whether the other schemas should follow. If it was unintended, revert the change.

## Steps to reproduce
1. POST /api/v1/users/signup with a unique email and an 8-character password

## Expected
200 (per the current plan and test).

## Actual
422 Unprocessable Content, because the password is shorter than the new 10-character minimum.
