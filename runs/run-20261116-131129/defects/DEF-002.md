# DEF-002: Sign-up minimum password length raised from 8 to 10 characters

- **Severity:** Sev3
- **Status:** Fixed (pending verification)
- **Classification (AI):** test_issue (confidence: medium)
- **AI recommendation:** update_test
- **Failing tests:** TC-005

- **Regression since app commit:** aabb901

## Root cause (AI)
The diff changed UserRegister.password min_length from 8 to 10, so an 8-character sign-up password now returns 422.

## Why this classification
The change looks like a deliberate tightening of password policy rather than a defect. A stricter minimum is a common, sensible change, and nothing else is broken. It is not certain, though. The change is inconsistent with UserCreate, UpdatePassword, NewPassword and UserUpdate, which still use min_length=8, so it may be an accidental or partial change. A human should confirm the intended policy. If 10 is the intent, update TC-005 (boundary 10 accepted, 9 rejected, 128 accepted, 129 rejected) and align the other schemas. If not, revert to 8.

## Steps to reproduce
1. POST /api/v1/users/signup with an 8-character password
2. Compare with the plan: 8 and 128 characters should be accepted, 129 rejected

## Expected
8-char password returns 200 (per the plan and the previous behaviour).

## Actual
422 Unprocessable Content, because the minimum is now 10.
