# DEF-001: Items list leaks other users' items (owner filter removed for non-superusers)

- **Severity:** Sev1
- **Status:** Fixed (pending verification)
- **Classification (AI):** product_bug (confidence: high)
- **AI recommendation:** fix_code
- **Failing tests:** TC-017, TC-043
- **Suspect module:** `backend/app/api/routes/items.py` read_items(), non-superuser else-branch: the diff removed `.where(Item.owner_id == current_user.id)` from both the count query and the item select
- **Regression since app commit:** aabb901
- **Run:** run-20261116-131129

## Root cause (AI)
The regression diff dropped the owner_id filter in the non-superuser branch of GET /items/. Any authenticated user now gets every user's items, and `count` is the global total.

## Why this classification
This is a data leak and an authorization failure, not a policy change. The endpoint's single-item routes (read, update, delete) still enforce ownership with 403, so the list route is now inconsistent with them. The UI test TC-043 fails for the same reason. User B sees A's item, so the empty state 'You don't have any items yet' never renders. The frontend code is correct and only displays what the API returns. No test change is warranted.

## Steps to reproduce
1. Create users A and B (non-superusers)
2. As A, create 2 items; as B, create 1 item
3. As A, GET /api/v1/items/
4. In the UI, log in as a new user B with no items and open /items

## Expected
A receives only A's 2 items with count=2. A user with no items sees the empty state.

## Actual
A receives all users' items (extra IDs present) and the count is the global total. User B sees A's items, so the empty state is never shown.
